# 团队销售工具全功能开发与迭代计划

更新时间：2026-06-03

## 1. 项目定位

Open Sales Assistant 的目标是做成一个团队和个人都可以自部署的智能销售助手工具，而不是商业 SaaS 平台。

它要解决的问题：

- 销售资料分散，销售新人很难快速掌握产品和话术。
- 客户咨询重复，团队需要统一、可维护的 FAQ 和顾虑应对。
- AI 可以帮助整理资料、生成待审核建议，但不能自动覆盖正式知识库。
- 小团队希望用一个简单系统管理销售资料、客户咨询、跟进记录和基础数据。

当前默认数据是培训机构销售场景，用作开源 demo。后续可逐步替换为更多行业示例，例如课程、软件、门店服务、顾问服务和 B2B 解决方案。

## 2. 当前能力

- Node.js + Express 单体服务。
- 前台咨询页、登录页和后台管理页。
- 本地 JSON 文件数据库 `data/db.json`。
- 素材上传、AI 分析、知识库建议审核。
- 销售话术、FAQ、顾虑应对、知识摘要维护。
- 客户资料、聊天记录、AI 画像、跟进记录。
- 证书查询作为 demo 业务模块。
- 数据导出、手动备份和基础部署文档。
- JSON 存储继续作为默认轻量模式保留，数据库适配作为后续可选能力。

## 3. 迭代路线

### P0：开源可运行版本

目标：让新用户克隆仓库后能在本地跑起来，理解 demo 数据和完整销售知识库流程。

要做：

- README、贡献指南、安全说明、许可证补齐。
- Demo 数据标注清楚，避免被误认为真实业务数据。
- `.env.example` 使用本地默认地址。
- 保留 JSON 数据库，便于快速试用。
- 增加基础测试和健康检查说明。

### P1：团队销售工作台

目标：让一个小团队可以围绕客户和线索协作。

要做：

- 销售成员、主管、管理员角色。
- 客户负责人、跟进状态、下次跟进时间。
- 今日待跟进、近期高意向客户、未回复客户视图。
- 客户标签、意向阶段、无效原因。
- 跟进记录搜索、筛选和导出。

### P2：知识库和 AI 质量增强

目标：让团队可控地使用 AI，而不是让 AI 直接改正式内容。

要做：

- 知识库版本历史和回滚。
- AI 建议采纳前可编辑。
- 素材编辑、搜索、批量操作。
- 知识冲突检测增强。
- Prompt 和回答质量评测样例。
- AI 用量日志和成本估算。

### P3：数据和部署增强

目标：让团队自部署更稳，降低数据丢失风险。

要做：

- 数据迁移机制持续完善。
- 备份恢复后台。
- 操作日志。
- PostgreSQL 或 MySQL 可选适配，但不移除 JSON 存储。
- 改进 Docker 部署和容器化自部署示例。
- 生产部署 checklist。

### P4：生态连接器

目标：让销售助手可以接入团队已有工具。

要做：

- 表单线索导入。
- Excel/CSV 客户和资料导入。
- CRM 示例连接器。
- 企业微信、飞书或 Slack 通知示例。
- MCP connector 示例，用于把销售资料和客户上下文暴露给 AI 工具。

## 4. 开源维护目标

- 每个迭代都保持自部署可用。
- 保留 JSON 存储，方便本地 demo、轻量自部署和贡献者测试。
- 不把客户数据、商业部署配置或私有 API key 放入仓库。
- 新功能优先用 demo 数据和可复现测试验证。
- 通过 issue 和 PR 维护路线，积累真实开源协作证据。
- 用 Codex 辅助 issue triage、PR review、测试生成、文档更新和 release notes。
